The Stack

Next.js, Sanity, Tailwind v4

Sheet 02 / 08

Every choice below is answering something the brief actually asked for, not filling out a default template.

RequirementWhy this stack answers it
“Exactly as Claude Design made it” The design is entirely CSS-custom-property driven, and Tailwind v4’s @theme is itself CSS variables. The tokens port verbatim — no translation layer, no rounded-off values.
Designs page and every project under CMS control next-sanity v11 defineLive gives real-time content with no cache plumbing; the Presentation tool gives click-to-edit against a live preview.
Findable by clients and tender bodies Server components ship real HTML. Per-page metadata from Sanity, generated sitemap and robots, and ProfessionalService JSON-LD carrying the Apire address and both phone numbers.
116 MB of project photography Sanity’s CDN handles transforms and modern formats; next/image handles sizing and blur-up placeholders.
A contact form that genuinely sends Web3Forms behind a Next.js route handler — the access key stays server-side and the submission gets validated and rate-limited before it leaves.
Edit content without touching code One singleton document per page plus a project collection. Every visible string on the site is a field.

Considered and set aside. Astro — you asked for React. A plain Vite SPA — gives up the SEO that a practice bidding public work actually needs. Embedding the Studio inside Next.js — slower builds, no auto-updates, and Sanity’s own guidance is against it.

// The whole port hangs on this bridge. @theme inline is load-bearing:
// with plain @theme, Tailwind emits the literal var() string into every
// utility and opacity modifiers like bg-ink-900/60 stop resolving.

@import "tailwindcss";
@import "./tokens/colors.css";      // verbatim from the design system
@import "./tokens/typography.css";

@theme inline {
  --color-gold-500:  var(--gold-500);      // → bg-gold-500, text-gold-500…
  --color-surface-deep: var(--surface-deep);
  --font-display:    var(--font-marcellus), Georgia, serif;
  --spacing-11:      128px;
  --ease-standard:   cubic-bezier(.22,.61,.36,1);
}

The token files are dropped in byte-identical. Re-run the import when the design changes and the whole site follows. The composite font: shorthands — --type-h1, --type-eyebrow — have no Tailwind equivalent, so they become a thin set of component classes used wherever a heading or eyebrow appears.

The design system’s fonts.css pulls Marcellus, Archivo and IBM Plex Mono from Google at runtime — a render-blocking third-party request and a guaranteed layout shift. Same faces, same weights, moved to next/font and self-hosted.

Numbering is derived, never typed

The brand numbers everything 01, 02, 03 — the design system is explicit that this is a system, not decoration. So editors never enter a number. Position in the ordered list produces it at render time.

Insert a project at position three and everything below renumbers, including the previous/next record links at the foot of each project page. Reordering is a drag in the Studio.

The Studio carries the brand law

The seven singletons pin to the top of the sidebar; projects sit below as a drag-orderable list. Every document gets an icon.

Field descriptions carry the rules that actually bite in daily editing: Ghanaian and British spelling — recognised, programme, centred. The practice writes wholistic, not holistic. No emoji. Exclamation marks only in the tagline.

Photography & The Form

Getting real content in

Sheet 04 / 08

Project Images → Sanity

A seed script walks the folder. Each folder name becomes the project title and slug; the main image becomes the thumbnail and the project hero; everything else joins the gallery, sorted naturally so Img_6 precedes Img_10.

Uploads dedupe on content hash, so re-running is safe. Documents are created as drafts with their order set — you review and publish.

One catch already handled: Agogo Makro spells its main image with a capital M, so the match is case-insensitive.

The enquiry form

The browser posts to a route handler, which posts to Web3Forms. Going through the server rather than straight from the page buys four things: the access key never enters the JavaScript bundle, submissions are validated before they can reach your inbox, an IP rate limit sits on top of Web3Forms’ own, and swapping provider later touches exactly one file.

A honeypot field is rejected server-side. The reply-to is set to the sender, and the subject names them, so replying is one click.

On success the form is replaced in place by the design’s own confirmation — gold rule, “Thank you.”, and the two-working-day promise with the direct line.

The Gap Ledger

Where design, brief and reality disagree

Sheet 05 / 08

You asked for the loopholes. These are all of them. Thirteen are closed by how the build is constructed; six need a decision from you.

01

No mobile design existsClosed

The design is desktop-only throughout: fixed 56 px gutters, a 44 px rail that would swallow a phone screen, a two-column comparison table, and a four-column project row.

Rather than invent a second visual language, the responsive behaviour is derived from rules the brand already states. Gutters step down. The rail collapses to a gold top bar. The header becomes lockup plus hamburger, using the veil-and-blur mobile menu the design system already specifies. The comparison table stacks into labelled pairs. No new colours, radii or type sizes are introduced.

02

A logo variant is referenced but missingClosed

The Logo component points at logo-lockup-ink.png, which isn’t in the project. It’s a print-only variant with no web use, so that branch is dropped rather than shipping a broken image.

03

“All 30+ projects” is hardcodedClosed

So are the 30+ / 20+ / 4 / 2013 figures. Left alone, the site would claim thirty commissions while displaying five. All become editable fields.

04

Featured projects are a hardcoded index tripletClosed

The home page picks items 1, 2 and 4 by position — which breaks the moment the list changes. It becomes an explicit picker capped at three, falling back to the first three by order.

05

Three image slots, but folders hold four to twelveClosed

The project page’s exact layout is kept — one large plate above two secondaries — and the remaining gallery images extend below it in the same language: plate grounds, square corners, mono captions below the frame and never over it. Faithful, rather than padded out.

06

Sector filters were scraped from free textClosed

A typo in one project would silently produce a sixth filter chip. Replaced with a reference to a controlled list.

07

Three accessibility slips in the designClosed

The project row is a clickable <div>, unreachable by keyboard — it becomes a link. The filter chip is a span with a button role — it becomes a real button. The previous/next links declare border-right twice in one style attribute. All corrected without moving a pixel.

08

The base stylesheet golds every link on the pageClosed

Correct for prose, wrong for nav, footer, cards and buttons — which is why the design overrides it inline nine separate times. Scoped to prose instead, so the overrides disappear.

09

Two names, two contextsClosed

“Bejewelled” in navigation, marketing and titles. “Bejewelled Enterprise” in the copyright line, the registration strip and the project record line. Both live in settings so an edit can’t collapse the distinction.

10

Header height contradicts itselfClosed

The design system says 72 px condensing to 56; the design file says 76 px. The design file wins — it’s the actual artefact — and the condensed state is dropped, since nothing in the design triggers it.

11

Hash routes become real URLsClosed

#/project/01 becomes /designs/agogo-makro. Necessary for indexing, sharing and analytics.

12

Fonts load from a third-party CDNClosed

Self-hosted instead. Same three faces, same weights, no render-blocking request.

13

The logo is a raster PNGClosed

Fine at the sizes used, including on retina. Worth commissioning a vector master eventually for print and large-format — the design system flags this too — but it doesn’t block anything here.

14

No Sanity project exists yetDecision

I can create one directly. I need to know which organisation it should sit under, or an existing project ID to reuse.

15

Five photographed folders, seven profile projects, one overlapDecision

Only the KATH Credit Union appears in both. Agogo Makro, Dekyi Appartments Gazebo, Gaze and Konkromase are new; six projects from the company profile have no photography at all.

My recommendation: publish the five photographed projects, and load the six profile projects into Sanity as unpublished drafts. The portfolio reads complete and honest today, and the moment photographs arrive it’s a publish rather than a data-entry session.

16

Four photographs the CMS can’t sourceDecision

The home hero, the portrait of Rosemary Dwamena, a site-works photograph for the construction page, and an office photo or map for contact. None are in the project folders.

Each is a Sanity image field, so all four are swappable without code. Until then the three scene shots fall back to the strongest project exteriors. The portrait has no honest substitute — that section renders without its image column rather than filling it with something generic.

17

Web3Forms access keyDecision

You create it against the inbox that should receive enquiries — a thirty-second signup. Until it arrives the form is fully built and the proxy returns a stubbed success in development.

18

Two folder names read as typosDecision

“Dekyi Appartments Gazebo” and “Agogo Makro”. Seeded exactly as named, per your instruction. Correcting the title in Sanity later takes seconds, and the slug is pinned on creation, so fixing a display name won’t break a live URL.

19

Visual editing is optionalDecision

The Presentation tool adds click-to-edit against a live preview. Genuinely useful, and also the piece most likely to need fiddling — so it’s scheduled last, where it can’t hold up launch.
